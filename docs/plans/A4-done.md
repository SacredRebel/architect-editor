# A4 — the editor under `/builder`, same origin

Branch `eco/a4`, from `eco/h19-2` @ `4b2ae1ba`.

The brief (architect, 28 Sep):

> the editor builds and runs correctly under the base path /builder (static export if the app allows it; if it cannot, say why and serve it with basePath on its own deployment). postMessage targetOrigin comes from one env with the production default https://spatial-map.vercel.app; messages from any other origin are ignored. Check: build, serve under /builder, record every request the page makes — zero 404s, zero requests outside /builder; --self-test forges one root-relative asset and must FAIL.

## Result

- **Static export: yes.**
  - `cd apps/editor && bun run build:static` writes `apps/editor/out/builder/`, with `basePath` and `assetPrefix` `/builder`. The export existed since E1.
  - App Router route handlers cannot be exported, so the build moves `app/api` aside and restores it. The static client never calls them (`isSceneServerAvailable()`).
- **The pages (`/builder/` and `/builder/embed/`): zero requests outside `/builder`, zero 404s, on both builds.**
- **postMessage origin:**
  - one env, `NEXT_PUBLIC_ECO_HOST_ORIGIN`, production default `https://spatial-map.vercel.app`;
  - the bridge posts only to that origin;
  - it ignores every message whose `event.origin` differs, `eco:hello` included.
- **Beyond the brief**, the same audit over real content:
  - the H19 house, site and trees, plus one KTX2 finish, over the bridge;
  - IFC export from the embed page.

  Both are same-origin apart from one named exception, which is open below.

How the base path is applied to public files:

- The export's text files are rebased onto the base path: 518 references in 43 files.
- The asset resolver uses the base path in static builds and is idempotent for paths that already carry it.
- A literal naming a file the export lacks keeps the CDN rather than becoming a 404.

The decoders and web-ifc read one setting, `configureDecoderPaths({ draco, basis, webIfc })` in the viewer:

- Its defaults are the old behaviour, so other consumers are unchanged.
- The editor sets it at startup to `<basePath>/…` (`apps/editor/lib/decoders-self-hosted.ts`).
- `scripts/copy-decoders.mjs` copies the files into `public/decoders/`. It runs beside the web-ifc copy on postinstall, predev and prebuild, and in the static export.
- The copies are not committed. `public/decoders/LICENSE` is the Apache-2.0 text, byte-identical to apache.org's (sha256 `cfc7749b…3d30`).

IFC export was broken, and not only under `/builder`:

- Unset, web-ifc resolves its wasm against the script that loaded it. In the bundle that is a chunk directory.
- The check caught it on the build before the fix. Export from `/builder/embed/` asked twice for `/builder/_next/static/chunks/web-ifc.wasm`, got 404 both times, and no file downloaded.
- The exporter now takes `wasmPath` (`packages/ifc-exporter`, ours from H16.5), and the editor passes the setting above.
- The same chunk-relative lookup applies at the root deployment, so H16.5's export was probably broken there as well. The Vercel preview is the place to confirm.

## Open for the architect

1. **235 library files exist only on Pascal's CDN.**
   - They are the wood, flooring and roofing finishes: 512 px KTX2 maps and `_thumb.webp` thumbnails. The build's list and a list derived from `core/src/material-library.ts` against `public/` agree exactly.
   - Upstream's own defaults use them:
     - slab tops and stair treads: `wood-woodplank48`;
     - roofs: `roof-terracottatiles`;
     - curated item models, through `pascal_material` tags in their glTF: coffee table, TV stand, bookshelf, dining set, bedside table, dresser and the trees.
   - So any ordinary house requests some of them. The H19 house requests six.
   - This repository holds full-size `.webp` originals of the same finishes, under upstream's MIT licence (Pascal Group Inc.). It does not hold the KTX2 derivatives the library points at.
   - Options:
     - (a) Download the 235 files from editor.pascal.app into `public/material/`. They are Pascal's own assets, but the download needs the human's approval and their licence recorded.
     - (b) Encode them from the committed originals with a KTX2 encoder (KTX-Software or basisu, both Apache-2.0). That is a new tool.
     - (c) Accept Pascal's CDN for these finishes.
   - Until one is chosen the build keeps them on the CDN (no 404s), and the check lists them on every run. Once they are in the export, `onCdn` is empty and the check allows nothing outside `/builder`, with no edit to the check.
2. **The item catalog names some models and thumbnails by absolute Supabase URL** (`editor/src/components/ui/item-catalog/catalog-items.tsx`). Browsing the catalog fetches them. They are upstream's; the page and the content load never request them.
3. **Local perf captures need the bridge origin.** The capture harness posts the fixture from the page's own origin. A build that captures through the bridge needs `NEXT_PUBLIC_ECO_HOST_ORIGIN` set to that origin, or the bridge now ignores the messages. H19's recorded captures are unaffected.
4. **What maps the world's `/builder` onto this build is not this repository's work.** Vercel's settings for this project are unchanged. Its existing `/builder` rewrites to `/` serve the root build, not this export.

  - The world frame (z south): terrain, guides, ghost snapping and the hello handler place the site there.
  - Editor +z as north: the sun and the GLB/walk export read it that way.
